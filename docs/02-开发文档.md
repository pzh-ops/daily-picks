## 3. 公共数据结构（models.py）

```python
from __future__ import annotations
from dataclasses import dataclass, field
from datetime import datetime

@dataclass(slots=True)
class Article:
    source: str                 # 'rss' | 'bilibili' | 'zhihu' | 'juejin'
    source_key: str             # 源内唯一 ID
    title: str
    url: str
    author: str | None = None
    summary: str | None = None
    published_at: datetime | None = None
    raw: str | None = None      # 源原始 JSON（调试用，可空）

    @property
    def content_hash(self) -> str:
        """跨源去重：sha256(title + '\n' + url) 十六进制。"""
        ...

@dataclass(slots=True)
class Pick:
    article_id: int
    rank: int
    reason: str

@dataclass(slots=True)
class RankResult:
    picks: list[Pick]
    ok: bool                    # LLM 输出是否有效（False → 调用方降级）
    tokens_in: int = 0
    tokens_out: int = 0
    raw_text: str = ""          # LLM 原始返回（调试/日志）

@dataclass(slots=True)
class PushResult:
    ok: bool
    channel: str                # 'wecom' | 'serverchan' | 'noop'
    detail: str

@dataclass(slots=True)
class ScoredArticle:
    article: Article
    score: float
    article_id: int | None = None   # DB 主键（M2）：LLM 候选 JSON 与降级 Pick 回指文章用
```

修订说明（2026-08-27，M2）：
- `ScoredArticle` 增补可选字段 `article_id: int | None = None`：LLM 候选 JSON（§4.12）与降级 `Pick.article_id` 均需 DB 主键回指文章，而 `Article` 无 id 字段；`rule_score` 等纯打分场景可不传（None）。

要点：
- `load_config` 对未知源 key（`sources.enabled` 之外）只警告不报错。

- `ConfigError` 定义于本模块，CLI 捕获后打印友好错误并退出码 2。
- `load_config` 会先加载同目录 `.env`（若存在；已存在的环境变量优先，不覆盖）。

- `sources` 类型由 `dict[str, SourceSection]` 改为 `SourcesConfig`：`enabled` 是 list，无法解析为 `SourceSection`，原类型与 `cfg.sources.enabled` 用法冲突。

### 4.3 storage.py

```python
class Storage:
    def __init__(self, db_path: Path): ...
    # 线程安全：单连接 + threading.RLock；connect(check_same_thread=False)

    def init_schema(self) -> None                          # 执行 §5 设计文档全部 DDL（幂等）
    def upsert_articles(self, articles: list[Article]) -> list[int]:
        """INSERT OR IGNORE 按 (source, source_key) 与 content_hash 去重；返回【新插入】的 article id 列表。"""
    def get_articles_by_ids(self, ids: list[int]) -> list[dict]:      # dict 含全部列
    def update_score(self, article_id: int, score: float) -> None
    def set_state(self, article_id: int, state: str) -> None          # state in {'new','dismissed'}
    def start_digest_run(self, run_date: str, candidate_count: int) -> int:
        """当日已有 run → 返回其 id（幂等）；否则插入并返回新 id。"""
    def finish_digest_run(self, run_id: int, *, picked_count: int, pushed: int,
                          channel: str | None, tokens_in: int, tokens_out: int,
                          cost_usd: float, fallback_used: bool) -> None
    def add_digest_items(self, digest_id: int, picks: list[Pick]) -> None
    def add_feedback(self, article_id: int, kind: str) -> None        # 同文章先删旧反馈再插入
    def get_feedback_kinds(self, article_id: int) -> list[str]
    def get_interest_weights(self) -> dict[str, float]                # 读 interest_weights 全表
    def bump_keyword_weight(self, keyword: str, delta: float) -> None # 钳制 [0.2, 2.0]，upsert
    def get_stats(self, days: int) -> dict:
        """返回 {'runs': n, 'pushed': n, 'tokens_in': n, 'tokens_out': n, 'cost_usd': x}（近 days 天）"""
```

要点：
- 所有写操作后 `conn.commit()`；单条读写失败抛 `StorageError`（定义于本模块）。
- `upsert_articles` 使用 `INSERT OR IGNORE` + `RETURNING id` 不行（兼容性）——正确做法：
  `INSERT OR IGNORE` 后对重复项 `SELECT id FROM articles WHERE source=? AND source_key=?`，返回全部 id 但只把**新插入**的交给上层打分（用 `cursor.rowcount` 判断：`rowcount==1` 为新增）。

### 4.4 sources/base.py

```python
class SourceError(Exception): ...          # 适配器内部使用，不向上抛

class SourceAdapter(ABC):
    name: str                              # 与 config.sources.enabled 中的名字一致

    def __init__(self) -> None:
        self.source_errors = 0             # 本次 fetch 源级错误计数（§6.7），fetch 开始时清零

    @abstractmethod
    async def fetch(self, cfg: SourceSection, client: httpx.AsyncClient) -> list[Article]:
        """拉取并清洗；任何异常自行捕获记日志，返回 []（或部分成功列表）。"""

    def _clean(self, title: str, summary: str | None, url: str) -> tuple[str, str | None, str]:
        """清洗：strip；空 title → raise SourceError；url 非 http(s) → raise SourceError；
        summary 去 HTML 标签（bs4）并截断 200 字。"""
```

模块级辅助函数：

```python
def to_local_datetime(value: int | str | None) -> datetime | None: ...
```
- unix 秒（int 或数字字符串）→ 本地 naive datetime；缺失/非法返回 None。bilibili/zhihu/juejin 的 `published_at` 统一走此函数。
- 修订说明（2026-08-27，M1）：掘金真实 API 的 `ctime` 为**字符串**（实测），§4.10 原代码
  `datetime.fromtimestamp(ai.get("ctime", 0))` 会抛 TypeError 导致本源整体失败；改为容错转换。
  缺失字段由默认 0（1970 噪音数据）改为 None（published_at 可空），§4.6/§4.7 同步调整。

class ZhihuAdapter(SourceAdapter):
    name = "zhihu"
    async def fetch(self, cfg, client) -> list[Article]:
        url = f"https://api.zhihu.com/topstory/hot-lists/total?limit={cfg.limit}"

                    summary=t.get("excerpt"), published_at=datetime.fromtimestamp(t.get("created", 0)))
```

### 4.12 llm.py

```python
INPUT_USD_PER_1M = 0.66     # deepseek-v4-pro 输入（缓存未命中/闲时）
OUTPUT_USD_PER_1M = 1.98

class LLMError(Exception): ...

class LLMClient:
    def __init__(self, cfg: LLMConfig): ...

    async def rank(self, candidates: list[ScoredArticle], profile: str,
                   top_n: int) -> RankResult:
        """1) 拼候选 JSON（见下）→ 2) chat() → 3) parse_response()
        网络/解析异常都返回 RankResult(ok=False)，不抛。"""
    async def _chat(self, messages: list[dict], **kw) -> dict:
        """POST {base_url}/chat/completions；tenacity 重试 3 次；
        返回完整 JSON（含 usage）；4xx 不重试直接抛 LLMError。"""
    @staticmethod
    def parse_response(text: str, valid_ids: set[int], top_n: int) -> RankResult:
        """剥离 ```json 围栏 → json.loads → 校验（设计文档 §7.2）→ RankResult(ok=True/False)"""
    @staticmethod
    def build_profile_json(weights: dict[str, float]) -> str: ...
```

候选 JSON 格式（`rank()` 构造，字段固定）：
```json
{"candidates": [{"article_id": 12, "title": "...", "summary": "...", "source": "bilibili"}]}
```

`_chat` 请求体：
```json
{"model": "deepseek-v4-pro", "messages": [...], "temperature": 0.3,
 "max_tokens": 2000, "response_format": {"type": "json_object"}}
```

成本计算：`cost_usd = tokens_in/1e6 * INPUT_USD_PER_1M + tokens_out/1e6 * OUTPUT_USD_PER_1M`。

修订说明（2026-08-27，M2）：
- 模块级函数 `build_candidates_json(candidates, max_input_chars) -> tuple[str, list[ScoredArticle], list[int]]`：
  按候选顺序拼接候选 JSON，超出 `max_input_chars` 截断（保留靠前候选）；返回（JSON 文本、实际发送候选、对应 article_id 列表）。`rank()` 与 `rank_and_pick()` 共用（同口径裁剪）。

`run_once` 步骤（顺序固定）：
1. `setup_logging`；`Storage(db).init_schema()`。
2. `run_date = now.astimezone(ZoneInfo(cfg.app.timezone)).strftime("%Y-%m-%d")`。
3. `run_id = storage.start_digest_run(run_date, candidate_count=0)`（幂等）。
4. `async with httpx.AsyncClient(timeout=...)`；`asyncio.gather` 并发各适配器 `fetch`（带 `asyncio.wait_for` 每源 30s 超时）。
5. 汇总 → `storage.upsert_articles()` → 对新文章取 `get_articles_by_ids` 构 `ScoredArticle`。
6. `weights = storage.get_interest_weights()` 合并 config 关键词（config 优先）。
7. `candidates = select_candidates(...)`；`rank_and_pick(...)`。无 DEEPSEEK_API_KEY 时打印并记日志
   "未配置 DEEPSEEK_API_KEY，使用规则分降级"，走规则分路径，run 不得崩溃。
8. `digest_text = build_digest_text(...)`。
9. 若 `dry_run`：写 `logs/last_digest.md`，`channel="dry-run"`，不调 webhook。
   否则 `publisher.push()`；`channel=provider`。
10. `finish_digest_run(...)` 记账（token/cost/fallback）。日志输出摘要：`采集 N 条，去重后 M 条，候选 K，精选 L，成本 $X`。

子命令实现要点：
- `init`：若 `config.yaml` 存在则询问覆盖（`--force` 跳过询问）；写 `.env.example`；`storage.init_schema()`。
- `feedback`：`like|dislike` 必填，`--keyword` 可选；找不到文章 → 退出码 1 + 提示。
- `stats`：`storage.get_stats(days)` 打印表格（文本）。
- `test llm`：发一条 1-token 请求验证连通与 key；`test push`：推一条"测试消息"。

## 5. 运行与部署

### 5.1 命令汇总

| 命令 | 作用 |
|---|---|
| `uv run daily-picks init` | 初始化 config.yaml + 数据库 |
| `uv run daily-picks run --dry-run` | 预览（写 logs/last_digest.md） |
| `uv run daily-picks run` | 立即完整执行 |
| `uv run daily-picks serve` | 常驻调度（默认 08:00） |
| `uv run daily-picks feedback like 12` | 反馈 |
| `uv run daily-picks stats --days 7` | 统计 |
| `uv run daily-picks test llm` / `test push` | 连通性自检 |

### 5.2 部署方式（推荐顺序）

1. **开发期**：`run --dry-run` 手动触发。
2. **常驻**：`nohup uv run daily-picks serve >> logs/serve.log 2>&1 &`（WSL 下最简；或 systemd user unit）。
3. **cron**（非 WSL 或已启用 cron 服务）：
   ```cron
   0 8 * * * cd ~/daily-picks && /home/yg/.hermes/bin/uv run daily-picks run >> logs/cron.log 2>&1
   ```
4. **WSL 提示**：WSL 默认不启动 cron；若用 Windows 计划任务，命令为
   `wsl.exe -d <distro> -- cd ~/daily-picks && uv run daily-picks run`。

## 6. 代码规范

- 类型注解全覆盖（`pyright`/mypy 友好）；公共函数必须有 docstring（一句话 + 参数说明）。
- 异步函数禁止调用阻塞 IO（feedparser 解析除外，量小可接受）。
- 异常策略：适配器内部吞异常记日志；`storage/llm/publisher` 抛自定义异常；CLI 顶层捕获。
- 所有时间统一本地时区 `Asia/Shanghai`；入库前 `datetime` 不带 tzinfo（本地 naive）。
- 日志必须包含可搜索上下文：`source=xxx article_id=xxx` 等。
- 提交前跑 `ruff check .` 与 `pytest`，全绿才提交。
