## 1. 项目概述

### 1.1 背景

个人开发者需要一个"能写进简历、真实每天都在用"的代表性项目。本项目是一个**微信推送的个人内容发现 Agent**：
每天自动从多个内容源聚合候选内容，用 LLM 按用户兴趣筛选、排序、去重，生成"每日精选"简报并推送到微信。

### 1.2 定位

> 最小可用的个人 Agent 范式：采集（Collect）→ 理解（Understand）→ 决策（Decide）→ 推送（Deliver），
> 外加一个可学习的偏好反馈闭环。

### 1.3 目标（成功标准）

- **P0**：每天 08:00（Asia/Shanghai）自动推送 ≤10 条精选到微信，用户每天愿意看。
- **P1**：连续稳定运行 30 天无人工干预；单源故障不影响整体。
- **P2**：单次运行 LLM 成本 < ¥0.2（约 $0.03）。
- **P3**：开源可复现——任何人配好 key 后 10 分钟内能跑起来。

### 1.4 命名与目录

- 项目代号：`daily-picks`
- 根目录：`~/daily-picks/`（本机），GitHub 仓库名 `daily-picks`
- Python 包名：`daily_picks`，命令行入口：`daily-picks`（`python -m daily_picks`）

### 4.2 数据流（一次运行）

1. `cli.run()` 读取配置 → 初始化 Storage（建表/迁移）→ 获取当日 digest_runs 幂等锁。
2. 并发采集：每个启用的 SourceAdapter 拉取各自内容，转为 `list[Article]`（源内部异常只记日志）。
3. 全部采集完成后，`Storage.upsert_articles()` 去重入库，返回**新入库**的 article id。
4. `Ranker.rule_score()` 给新文章打分 → 取 Top `max_candidates`(40) 作为 LLM 候选。
5. `LLMClient.rank()` 用兴趣画像 prompt 精排 → 解析 JSON 得到 Top `top_n`(10) + 理由。
   - 解析失败/非法 → 降级：直接取规则分 Top 10（`fallback_used=True` 记日志）。
6. `Digest.build_digest_text()` 生成微信 markdown 文本。
7. `Publisher.push()` 推送；写 `digest_runs`/`digest_items` 记录（含 token 与成本）。
8. dry-run 模式：步骤 7 改为写 `logs/last_digest.md`，不调用 webhook。

## 5. 数据模型（SQLite DDL）

文件：`data/daily_picks.db`。初始化：`Storage.init_schema()`，幂等（`CREATE TABLE IF NOT EXISTS`）。

```sql
CREATE TABLE IF NOT EXISTS articles (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    source       TEXT    NOT NULL,                -- 'rss'|'bilibili'|'zhihu'|'juejin'|'hnews'|'infoq'
    source_key   TEXT    NOT NULL,                -- 源内唯一 ID（aid/question_id/article_id/guid）
    title        TEXT    NOT NULL,
    url          TEXT    NOT NULL,
    author       TEXT,
    summary      TEXT,                            -- 一句话摘要（截断 ≤200 字）
    content_hash TEXT    NOT NULL UNIQUE,         -- sha256(title + url)，跨源去重
    published_at DATETIME,                        -- 源发布时间（本地时区）
    fetched_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    score        REAL    NOT NULL DEFAULT 0,      -- 最近一次规则分
    state        TEXT    NOT NULL DEFAULT 'new',  -- new | dismissed
    UNIQUE(source, source_key)
);
CREATE INDEX IF NOT EXISTS idx_articles_published ON articles(published_at DESC);

CREATE TABLE IF NOT EXISTS digest_runs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    run_date        TEXT NOT NULL UNIQUE,         -- 'YYYY-MM-DD'，幂等键
    candidate_count INTEGER NOT NULL DEFAULT 0,
    picked_count    INTEGER NOT NULL DEFAULT 0,
    pushed          INTEGER NOT NULL DEFAULT 0,   -- 0/1
    channel         TEXT,                         -- 'wecom'|'serverchan'|'dry-run'
    llm_tokens_in   INTEGER NOT NULL DEFAULT 0,
    llm_tokens_out  INTEGER NOT NULL DEFAULT 0,
    cost_usd        REAL    NOT NULL DEFAULT 0,
    fallback_used   INTEGER NOT NULL DEFAULT 0,   -- 是否因 LLM 异常降级
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS digest_items (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    digest_id   INTEGER NOT NULL REFERENCES digest_runs(id),
    article_id  INTEGER NOT NULL REFERENCES articles(id),
    rank        INTEGER NOT NULL,
    llm_reason  TEXT,
    UNIQUE(digest_id, article_id)
);

CREATE TABLE IF NOT EXISTS feedback (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    article_id  INTEGER NOT NULL REFERENCES articles(id),
    kind        TEXT NOT NULL CHECK (kind IN ('like','dislike')),
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS interest_weights (
    keyword    TEXT PRIMARY KEY,
    weight     REAL NOT NULL DEFAULT 1.0,         -- 范围 [0.2, 2.0]
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**幂等规则**：`digest_runs.run_date` 唯一。当天第二次触发时，`start_digest_run()` 返回已有 run id，采集与排序仍会执行（用于补跑），但推送前检查 `pushed=1` 则跳过推送，仅更新统计。

## 6. 内容源适配器设计

统一接口（见开发文档 §4.5）：`async fetch(...) -> list[Article]`。**字段映射**如下，实现必须严格对应。

### 6.1 通用 RSS（`rss`）

- 请求：`GET {url}`，UA 必填。
- 解析：feedparser。
- 字段映射：`entry.title→title`；`entry.link→url`；`entry.summary→summary`（去 HTML 标签后截断）；`entry.published_parsed→published_at`（无则用当前时间）；`entry.author→author`；`entry.id 或 entry.link→source_key`。
- 默认源：少数派 `https://sspai.com/feed`、阮一峰 `https://www.ruanyifeng.com/blog/atom.xml`（可在 config 增删）。

### 6.2 B站热门（`bilibili`）

- 请求：`GET https://api.bilibili.com/x/web-interface/popular?ps={ps}&pn=1`，UA 必填（无 UA 会被拒）。
- 已实测：`code==0` 为成功；`data.list[]` 为条目。
- 字段映射：

| API 字段 | Article 字段 |
|---|---|
| `data.list[].aid` | `source_key`（str） |
| `data.list[].bvid` | 拼 URL：`https://www.bilibili.com/video/{bvid}` |
| `data.list[].title` | `title` |
| `data.list[].owner.name` | `author` |
| `data.list[].desc` | `summary`（截断 200 字） |
| `data.list[].pubdate` | `published_at`（unix 秒 → 本地时区） |

### 6.3 知乎热榜（`zhihu`）

- 请求：`GET https://api.zhihu.com/topstory/hot-lists/total?limit={limit}`，Header：`UA` + `Accept: application/json`。
- 已实测：顶层 `data[]` 为热榜条目，`target` 为问题对象。
- 字段映射：

| API 字段 | Article 字段 |
|---|---|
| `data[].target.id` | `source_key`（str） |
| `data[].target.url` | `url`（将 `api.zhihu.com` 替换为 `www.zhihu.com`，移动端可正常打开） |
| `data[].target.title` | `title` |
| `data[].target.excerpt` | `summary`（截断 200 字） |
| `data[].target.created` | `published_at`（unix 秒） |
| `data[].target.answer_count` | 不进库；可在 raw 中保留 |

- 限流注意：若返回 429/403 或 `data` 为空，视为该源本次失败，记日志后跳过。

### 6.4 掘金推荐（`juejin`）

- 请求：`POST https://api.juejin.cn/recommend_api/v1/article/recommend_all_feed`，Header：`UA` + `Content-Type: application/json` + `Origin: https://juejin.cn`。
- Body：`{"id_type": 2, "sort_type": 200, "cursor": "0", "limit": {limit}}`。
- 已实测：`err_no==0` 为成功；`data[]` 为条目。
- 字段映射：

| API 字段 | Article 字段 |
|---|---|
| `data[].item_info.article_id` | `source_key`（str） |
| `data[].item_info.article_info.title` | `title` |
| `data[].item_info.article_info.brief_content` | `summary` |
| `data[].item_info.author_user_info.user_name` | `author` |
| `data[].item_info.article_info.ctime` | `published_at`（unix 秒） |
| 拼接 | `url = https://juejin.cn/post/{article_id}` |

### 6.5 Hacker News（`hnews`）

- 请求：`GET https://hn.algolia.com/api/v1/search?tags=front_page&hitsPerPage={hits_per_page}`，UA 必填。
- 已实测：返回 `hits` 数组（Algolia 格式，单请求即可，无需两步取 item）。
- 字段映射：

| API 字段 | Article 字段 |
|---|---|
| `hits[].objectID` | `source_key`（str） |
| `hits[].title` | `title` |
| `hits[].url` | `url`；为空/缺失（Ask HN 帖）时回退 `https://news.ycombinator.com/item?id={objectID}` |
| `hits[].author` | `author` |
| `hits[].created_at` | `published_at`（ISO 8601 含 `Z`，解析为本地时间） |
| `hits[].points` | 不进库（raw 保留） |

- 网络注意：HN 为境外服务；若部署环境不可达则本源失败隔离（不影响其他源）。可用 `HTTP_PROXY/HTTPS_PROXY` 环境变量走代理（httpx 自动读取）。

### 6.6 InfoQ（`infoq`）

- 请求：`GET {url}`，默认 `https://www.infoq.cn/feed`（RSS 2.0，已实测 20 条）。
  ⚠️ **不要用 `https://www.infoq.cn/rss`**（返回 HTML 页面，已实测验证）。
- 实现：复用 RssAdapter 解析逻辑（子类继承），仅固定 `name="infoq"` 与默认 URL。
- 字段映射：同 §6.1 通用 RSS。

### 6.7 适配器通用规则

- 每个适配器返回前做**字段清洗**：strip、空标题丢弃、URL 必须 http(s) 开头、summary 去 HTML 标签。
- 每源 `max_items_per_source` 截断（默认 30）。
- 异常（网络/解析/字段缺失）由适配器内捕获并记日志，**不得抛出**——返回空列表并计数 `source_errors`。

## 7. 排序与 LLM 精排

### 7.1 规则打分（Ranker.rule_score）

```
score = keyword_score + source_weight + recency_bonus + feedback_bias

keyword_score = Σ( 关键词权重 × 命中次数 )，在 title+summary 中做子串匹配（大小写不敏感），
                每个关键词单篇文章最多计 3 次命中。
source_weight = 来源加成（config.sources.<name>.weight，默认 0）
recency_bonus = published_at 距今 ≤24h → +2.0；≤48h → +1.0；>48h → 0
feedback_bias = 该文章若已有 like 历史 → +1.0；dislike 历史 → -1.0（每文章一次）
```

- 保底策略：若规则分 Top `max_candidates` 全为 0 分（无关键词命中），则取**每个源分数最高的 1 条**补齐候选，保证 LLM 有材料可选。
- `select_candidates()` 返回 `list[(Article, float)]`，按分数降序，取前 `max_candidates`。

### 7.2 LLM 精排（LLMClient.rank）

- 接口：OpenAI 兼容 `POST {base_url}/chat/completions`，model=`deepseek-v4-pro`。
- 参数：`temperature=0.3`、`max_tokens=2000`、`response_format={"type":"json_object"}`。
- 输入裁剪：所有候选的 `title + summary` 拼接，超 `max_input_chars`(12000) 截断（按候选顺序保留靠前的）。
- **System prompt（固定模板，实现原样使用）**：

```
你是一个个人内容精选助手。用户每天会收到你挑选的 {top_n} 条内容。
候选列表用 JSON 数组给出，每个元素含 article_id/title/summary/source。
用户兴趣画像（关键词权重，数值越大越重要）：
{profile_json}

要求：
1. 从候选中选出恰好 {top_n} 条最符合用户兴趣的内容（候选不足则全选）。
2. 排除：标题党、广告、重复讨论同一事件的内容、纯口水/无信息量内容。
3. 多样性优先：尽量覆盖不同来源与话题，不要全选同一来源。
4. 只输出 JSON，不要任何其他文字，格式：
{"picks":[{"article_id": <整数>, "rank": <1..N>, "reason": "<30字以内中文理由>"}]}
```

- 用户消息：候选 JSON 数组（字段固定：`article_id`、`title`、`summary`、`source`）。
- 响应解析：剥离可能的 ```json 围栏 → `json.loads` → 校验：
  - `picks` 为 list；每项 `article_id` 必须存在于候选集合；`rank` 无重复；条数 ≤ `top_n`。
  - 校验失败任一 → 返回 `RankResult(ok=False)`，由 ranker 降级。
- 重试：`tenacity` 指数退避，对 5xx / 429 / 超时重试 3 次；`retry_if_exception_type(httpx.HTTPStatusError | httpx.TimeoutException)`。
- 成本：从响应 `usage.prompt_tokens` / `usage.completion_tokens` 记账；单价常量：
  `INPUT_USD_PER_1M=0.66`、`OUTPUT_USD_PER_1M=1.98`（deepseek-v4-pro 闲时缓存未命中价）。

### 7.3 降级策略

LLM 不可用/输出非法 → 使用规则分 Top `top_n`，`fallback_used=1` 记入 digest_runs，日志 WARNING，推送照常。

2. 【B站】世界伊始——《伊莫》全球上线定档
   摘要：PC端9月16日，移动端9月23日…
   作者：伊莫 ｜ 链接：https://www.bilibili.com/video/BV1wwhG6JEnc
```

规则：
- 标题行固定 `📌 今日精选 · {YYYY-MM-DD}`；序号 1..N；每条 `【来源】标题`。
- 摘要截断 60 字（`truncate(s, 60)`，中文按字符计）。
- 来源标签映射：`rss→源名(取 config 中 rss.urls 对应域名) / bilibili→B站 / zhihu→知乎 / juejin→掘金 / hnews→HN / infoq→InfoQ`。
- **企业微信 markdown 不支持链接渲染**：wecom 渠道使用 `msgtype=text`，链接以纯文本 URL 展示；
  Server酱渠道使用 markdown（支持 `[文字](url)`，故摘要行改为 `[链接](url)`）。

## 9. 推送渠道设计

### 9.1 企业微信机器人（默认，wecom）

- 创建：企业微信群 → 添加群机器人 → 复制 webhook key。
- 请求：`POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key={key}`
- Body：`{"msgtype": "text", "text": {"content": "{digest_text}"}}`
- 成功判定：`errcode == 0`。失败码 93000（key 无效）记 ERROR。
- 消息长度限制 2048 字节，超长按字符安全截断（截断函数 `truncate_bytes`，不允许切断 UTF-8 多字节字符）。

### 9.2 Server酱（备选，serverchan）

- 请求：`POST https://sctapi.ftqq.com/{sendkey}.send`
- Body（form）：`title=今日精选&desp={markdown_text}`
- 成功判定：`code == 0`。

### 9.3 统一接口

```python
class Publisher(ABC):
    async def push(self, title: str, content: str) -> PushResult: ...
```
`PushResult(ok: bool, channel: str, detail: str)`。`push.provider == "none"` 时用 `NoopPublisher`（只写本地文件，等价 dry-run）。

## 10. 偏好学习（反馈闭环）

- 入口：`daily-picks feedback like|dislike <article_id>`（也可 `--keyword 附加关键词`）。
- 规则（`feedback.py::apply_feedback`）：
  - **like**：取文章 title+summary 中命中的关键词，各 `weight += 0.1`（上限 2.0）；无命中时若提供了 `--keyword` 则给该词 +0.1 并插入。
  - **dislike**：命中关键词各 `weight -= 0.05`（下限 0.2）；该文章 `state='dismissed'`。
  - 同文章重复反馈：只计最后一次（先删该 article 旧反馈再插入）。
- 权重存 `interest_weights` 表；`ranker` 每次运行时读取最新权重。
- v2 路线（本期不实现，文档预留）：点击追踪链接（部署到免费托管平台记录点击 → 自动 like）。

## 12. 调度与运行模式

| 模式 | 命令 | 说明 |
|---|---|---|
| 一次性 | `daily-picks run` | 立即执行完整流程（cron/systemd timer 推荐方式） |
| 预览 | `daily-picks run --dry-run` | 不推送，写 `logs/last_digest.md` |
| 常驻 | `daily-picks serve` | APScheduler 到点执行，进程常驻 |
| 自检 | `daily-picks test llm` / `test push` | 连通性检查 |
| 反馈 | `daily-picks feedback like|dislike <id>` | 偏好学习 |
| 统计 | `daily-picks stats [--days 7]` | 推送记录/token/成本 |

- 常驻调度：APScheduler `BlockingScheduler`，`CronTrigger(hour=8, minute=0, timezone="Asia/Shanghai")`。
- 幂等：`digest_runs.run_date` 唯一键（§5）。
- WSL 注意：cron 服务默认不启动，推荐 `serve` 模式或 Windows 计划任务；文档提示用户即可。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 内容源 API 变更/风控（知乎/B站） | 采集失败 | 适配器独立 + 失败隔离；RSS 兜底；预留 RSSHub 支持（把 RSSHub 地址当普通 RSS 配） |
| Hacker News 为境外服务，网络不可达 | hnews 采集失败 | 失败隔离不影响其他源；部署环境可用 `HTTP_PROXY/HTTPS_PROXY` 代理（httpx 自动读取） |
| LLM 输出不稳定 | 精选质量波动 | 严格 JSON 校验 + 降级；system prompt 强调多样性 |
| 推送 webhook 失效 | 收不到推送 | 重试 3 次；`test push` 自检；日志告警 |
| 关键词权重跑偏 | 内容单一化 | 权重上下限 [0.2, 2.0]；多样性 prompt 约束 |
| WSL 下 cron 不可用 | 不自动运行 | serve 常驻模式 + Windows 计划任务替代 |
