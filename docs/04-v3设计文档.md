# DailyPicks v3 设计文档 — 深度内容精选（docs/04）

> 版本：v3.0.0 草案 ｜ 日期：2026-08-31 ｜ 关联：docs/01（v1/v2 基准）、docs/05（开发文档）、docs/06（测试文档）
> 本文件是 v3 的唯一事实来源。所有函数签名、表字段、配置键以本文为准，实现禁止自行改名（AGENTS.md 第 4 条）。

## 1. 背景与目标

v1/v2 的定位是"聚合 + 精选"：6 个内容源海量采集 → 规则分 + LLM 精排 → 推 10 条。用户实际使用后反馈核心问题：
**信息太杂、太浅**——RSS 聚合内容居多，缺乏有深度思考的内容，与"快节奏时代看深度内容"的诉求不符。

v3 定位转变：**少而精的深度内容**。不追求覆盖量，追求每条都有思考深度。

### 1.1 目标（非功能）

| 编号 | 目标 |
|---|---|
| G-01 | 每天推送 5 条（默认）深度内容，宁缺毋滥 |
| G-02 | 推送格式：来源+标题、关键词（替代摘要）、具体推荐理由、链接/作者 |
| G-03 | 用户首次启动时通过向导完成标签/信息源/条数配置，可随时重跑 |
| G-04 | 点击与反馈（含文字反馈）持续演化筛选条件与标签，不局限于初始选择 |

### 1.2 边界（不做）

- 不做 App/网页端（保持微信文字推送）
- 不做内容生产（纯聚合与精选）
- 企业微信双向回调（需求 5 的通道 2）**本期不做**，但反馈入口必须做成适配器，后期可无缝切换

### 3.1 流水线变化（run 流程）

v2: 采集 → 去重入库 → 规则打分 → select_candidates → LLM 精排 → 推送
v3: 采集 → 去重入库 → 规则打分 → **deep 阶段（LLM 深度评分+关键词，过滤 < 阈值）** → select_candidates(min_score) → LLM 精排 → **v3 模板推送**

deep 阶段只对规则分 Top-N 候选执行（控制 LLM 成本，N = max_candidates）。

## 4. 数据模型（新表，DDL 锁定）

```sql
-- 用户画像（setup 向导产物，单用户单行）
CREATE TABLE IF NOT EXISTS user_profile (
    id          INTEGER PRIMARY KEY CHECK (id = 1),   -- 强制单行
    tags        TEXT NOT NULL DEFAULT '[]',           -- JSON 数组，如 ["AI大模型","创业"]
    sources     TEXT NOT NULL DEFAULT '[]',           -- JSON 数组，源 key 列表（含自定义）
    top_n       INTEGER NOT NULL DEFAULT 5 CHECK (top_n BETWEEN 1 AND 10),
    updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 标签权重（点击/反馈/手动演化，驱动关键词与来源选择）
CREATE TABLE IF NOT EXISTS tag_weights (
    tag        TEXT PRIMARY KEY,
    weight     REAL NOT NULL DEFAULT 1.0,             -- 范围 [0.2, 2.0]
    source     TEXT NOT NULL DEFAULT 'manual',        -- 'manual'|'click'|'feedback'
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 文字反馈记录（Hermes 通道 / 未来企微回调）
CREATE TABLE IF NOT EXISTS feedback_text (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    raw_text        TEXT NOT NULL,                    -- 用户原始反馈文字
    intent          TEXT NOT NULL CHECK (intent IN ('like','dislike','expand','adjust','none')),
    article_id      INTEGER,                          -- 可选：针对某条
    extracted_tags  TEXT NOT NULL DEFAULT '[]',       -- JSON 数组：反馈中提取的新标签
    keywords        TEXT NOT NULL DEFAULT '[]',       -- JSON 数组：提取的关键词（进 interest_weights）
    channel         TEXT NOT NULL DEFAULT 'hermes',   -- 'hermes'|'wecom'
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 自定义信息源注册表（setup 生成 + 运行维护）
CREATE TABLE IF NOT EXISTS source_registry (
    key        TEXT PRIMARY KEY,                      -- 源 key（rss 自定义源的唯一标识）
    name       TEXT NOT NULL,                         -- 显示名
    kind       TEXT NOT NULL DEFAULT 'rss',           -- 'rss'|'builtin'
    url        TEXT,                                  -- rss url（kind='rss' 必填）
    tags       TEXT NOT NULL DEFAULT '[]',            -- JSON 数组：关联标签
    enabled    INTEGER NOT NULL DEFAULT 1,
    added_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 4.1 兼容性

- articles/feedback/interest_weights/clicks/meta/digest_* 全部不动
- feedback 表（like/dislike）保留；feedback_text 是新入口，处理后同样写 interest_weights

## 5. 配置设计（config.yaml v3 段）

```yaml
profile:
  enabled: true            # false = 完全走 v2 行为
  top_n: 5                 # 每日推送条数，setup 写入，范围 1-10
  deep_threshold: 60       # 深度评分阈值（0-100），低于此值不推送
  deep_candidates: 40      # deep 阶段最多评分的候选数（LLM 成本控制）
  tags: []                 # setup 写入（JSON 数组，实际存 user_profile 表）
  sources: []              # setup 写入
feedback:
  channel: hermes          # 'hermes'（本期）| 'wecom'（后期）
  extract_keywords: true   # 反馈文字是否提取关键词写入 interest_weights
```

`config.py` 新增：

```python
class ProfileConfig(BaseModel):
    enabled: bool = False          # v3 默认关，setup 后开
    top_n: int = 5
    deep_threshold: int = 60
    deep_candidates: int = 40
    tags: list[str] = []
    sources: list[str] = []

class FeedbackConfig(BaseModel):
    channel: str = "hermes"
    extract_keywords: bool = True

class RootConfig(BaseModel):  # 追加
    profile: ProfileConfig = ProfileConfig()
    feedback: FeedbackConfig = FeedbackConfig()
```

### 6.2 `daily_picks/deep.py` — 深度评分 + 关键词提取（M11 核心）

```python
DEEP_SCORE_MIN: float = 0.0    # LLM 深度评分（0-100）输出下限校验
KEYWORDS_MIN: int = 3
KEYWORDS_MAX: int = 5

@dataclass
class DeepResult:
    article_id: int
    deep_score: int             # 0-100
    keywords: list[str]         # 3-5 个
    reason: str                 # 具体推荐理由（引用文章细节，禁止空泛）
    ok: bool                    # LLM 输出有效？

async def deep_analyze(article: Article, llm: LLMClient,
                       weights: dict[str, float]) -> DeepResult:
    """LLM 深度分析：输入 title+summary+url，输出 {deep_score, keywords, reason}。
    reason 要求：必须引用文章的具体观点/数据/场景，禁止 '本文深入浅出' 类空话。"""

async def deep_filter(candidates: list[ScoredArticle], llm: LLMClient,
                      threshold: int,
                      weights: dict[str, float] | None = None) -> tuple[list[ScoredArticle], list[DeepResult]]:
    """批量 deep_analyze（并发 ≤3），保留 deep_score >= threshold 的候选。
    失败/超时的文章降级为保留（fail-open，不因 deep 故障丢候选）。
    返回 (过滤后候选, 全量 DeepResult 列表)。"""

def format_keywords(keywords: list[str]) -> str:
    """'k1、k2、k3' 顿号拼接，超 5 个截断。"""
```

### 6.3 `daily_picks/feedback.py` — 反馈解析与演化（M12/M13）

```python
FEEDBACK_INTENTS = ("like", "dislike", "expand", "adjust", "none")

@dataclass
class ParsedFeedback:
    raw: str                    # 原始反馈文字（落 feedback_text.raw_text）
    intent: str                 # 见 FEEDBACK_INTENTS
    article_id: int | None
    tags: list[str]             # 提取的新标签（intent=expand）
    keywords: list[str]         # 提取的关键词（写 interest_weights）
    top_n: int | None           # intent=adjust 时的新条数

async def parse_feedback(raw: str, llm: LLMClient) -> ParsedFeedback:
    """LLM 解析文字反馈：意图识别 + 标签/关键词提取（JSON 输出）。"""

def apply_feedback(fb: ParsedFeedback, storage: Storage,
                   extract_keywords: bool = True) -> None:
    """落库 feedback_text + 演化：
    - like/dislike：原文 article_id 命中 → 写 feedback 表（复用 v1 逻辑）+ tag_weights 联动
    - expand：新标签写 tag_weights(source='feedback')，并扩 interest_weights
    - adjust：top_n 写 user_profile
    - 关键词：extract_keywords 时写 interest_weights（clamp [0.2, 2.0]）"""

def evolve_weights(storage: Storage) -> None:
    """点击/反馈驱动的权重演化（M13）：
    1. clicks 增量 → 命中文章 title+summary 关键词 +0.05（复用 tracking.apply_click 逻辑）
    2. feedback_text.intent='expand' 的标签 → 对应关键词权重 +0.1
    3. 所有权重 clamp [0.2, 2.0]"""
```

- 修订说明（2026-08-31）：ParsedFeedback 增 raw 字段（feedback_text.raw_text 为 NOT NULL，
  落库需要原文）；apply_feedback 为同名分派——首参为 ParsedFeedback → v3 文字反馈路径；
  否则保持 v1 签名 apply_feedback(storage, article_id, kind, extra_keyword=None) 行为不变

## 7. 推送格式规格（v3 模板）

```
📚 今日深度精选（5条）
──────────────
【Hacker News】标题：xxx
关键词：A、B、C
推荐理由：文章用 X 数据论证了 Y 观点，其中 Z 的对比特别值得注意……
链接：https://...
作者：xxx
──────────────
（后续条目同上）
```

- 理由约束：≥2 句话；必须包含文章具体信息（数据/观点/场景）；禁用词列表写死在 prompt：`深入浅出|受益匪浅|干货满满|值得一读|不容错过`
- 关键词：3–5 个，名词短语优先，来自 title+summary 原文

## 10. 风险与降级

| 风险 | 降级 |
|---|---|
| deep 阶段 LLM 失败 | fail-open：deep 失败文章保留为候选（§6.2） |
| deep 过滤后候选 < top_n | 降低阈值重试一次（threshold-10）；仍不足则按现有数量推送（宁缺毋滥） |
| 自定义 RSS 源不可达 | 复用现有失败隔离，不影响其他源 |
| 无 LLM 密钥 | setup 降级为纯内置映射（无 LLM 推荐）；deep 阶段跳过 → 行为等同 v2 |
| 文字反馈解析失败 | intent='none' 落库不演化，不抛错 |
